# TerraForge · 用户手册

> 适用对象：项目经理、技术质量部、资料员、施工工程师、平台运维管理员
> 版本：v1.0.0

---

## 1. 平台概述

TerraForge 是面向土木工程行业的企业级 RAG 智能知识平台。它把企业内部散落的技术资料（标准规范 / 项目案例 / 企业知识）汇聚成"可问答的知识库"，让一线工程师用自然语言直接获取准确答案和条文出处，避免在文档里大海捞针。

**平台的三条硬性承诺**：

| 承诺 | 实现方式 |
| --- | --- |
| 所有回答都能追溯到原始条文 | Stage6 强制引用增强，答案带 `[n]` 编号，点击可查看原文片段 |
| 依据不足时不硬答 | Stage7 置信度低于 0.45 时强制提示人工复核；无召回时直接提示补充资料 |
| 知识库能持续保鲜 | Stage7 健康体检 + 治理事项 + 知识盲区 + 运营报告闭环 |

## 2. 角色与典型场景

| 角色 | 典型问题 | 对应功能 |
| --- | --- | --- |
| 现场施工员 | "C60 混凝土冬期施工养护时间要求是什么？" | 工程规范智能查询 |
| 项目技术负责人 | "现浇楼板出现 0.4mm 裂缝，可能原因和处理措施有哪些？" | 施工质量问题分析 |
| 方案编制员 | "深 8m 基坑监测方案要点，含监测项目和报警值。" | 施工方案智能生成 |
| 投标 / 复盘人员 | "有哪些类似深基坑变形超限处置案例可参考？" | 工程案例经验检索 |
| 资料员 / 知识治理员 | 上传新规范、跟踪治理事项、生成运营报告 | 知识库 / 文档 / 治理模块 |

## 3. 工程智能问答

### 3.1 发起提问

进入 **工程智能问答** 页：

1. 左下角填写 **工程上下文**（项目名称 / 项目类型 / 专业 / 地区）—— 这些信息进入 Stage0，会影响 Stage2 的查询改写与 Stage3 的领域加权
2. 输入框上方选择 **目标知识库 / 知识域**（均可多选，留空表示全部）
3. 输入问题，`Enter` 发送，`Shift + Enter` 换行

首次进入时页面提供四张场景卡片，点击即可发起一次示例提问。

### 3.2 答案怎么读

每条助手回复包含：

- **意图标签**：`规范条文查询` / `质量问题分析` / `方案生成` / `案例检索` / `日常交流` / `未识别`
- **置信度标签**：高（≥0.75）/ 中（0.45~0.75）/ 低（<0.45）
- **耗时**：端到端毫秒数
- **答案正文**：带 `[n]` 引用编号，编号高亮显示
- **引用来源面板**：列出每条引用的标准编号、文档名、条文号、章节路径、相关度，点击任意一条打开右侧抽屉查看原文片段
- **低置信警示条**：置信度不足时出现橙色告警，提示由专业工程师复核后使用

> 若答案中没有任何 `[n]` 编号，说明知识库当前覆盖不足。此时系统不会编造内容，而会提示补充资料——请到"知识治理 → 知识盲区"生成补录事项。

### 3.3 右侧观测面板

- **执行链路**：Stage0→Stage7 每一步的名称、耗时、关键中间产物（改写后的查询、召回量、重排输入输出、上下文字符数、置信度信号明细）
- **召回片段**：完整候选切片列表，每条展示 5 个分数：向量 / BM25 / 融合 / 重排 / 最终

这两个面板是排查"为什么答成这样"的第一入口。

### 3.4 反馈

每条回答下方有 **有帮助 / 需改进**：

- **有帮助**：记为正向样本
- **需改进**：弹窗填写原因（如引用条文过期、答非所问、缺少依据），该问题将自动进入 **知识盲区** 分析池

### 3.5 多轮会话

左侧会话列表自动保存所有历史会话，点击即可加载完整消息与引用。点击 **新建会话** 开启一个独立上下文；点击会话右侧垃圾桶图标删除。

## 4. 知识片段检索（纯检索）

适用于"只想看命中了哪些条文，不需要生成答案"的场景。

操作路径：**知识片段检索** → 输入关键词或完整问题 → 选择知识库 / 知识域 / Top-K / 是否启用重排序 → 检索。

页面提供快捷示例标签（基坑监测报警值、混凝土养护时间等），点击直接检索。

结果中每条片段都会展示五维分数条，常用于：
- 检索质量评估（对比不同 Embedding / 重排策略）
- 资料员核查某标准是否已被知识库覆盖
- 定位"为什么这条没被召回"

## 5. 知识库管理

### 5.1 三域模型

| 知识域 | 收录内容 | 示例 |
| --- | --- | --- |
| 建设规范库 `standard` | 国家 / 行业 / 地方标准、规范、图集、强制性条文 | GB50204、JGJ130、GB50108 |
| 项目案例库 `case` | 典型工程案例、事故复盘、变更与索赔记录 | 深基坑变形超限处置复盘 |
| 企业知识库 `enterprise` | 企业标准、施工工法、SOP、专家经验、内部制度 | 混凝土浇筑作业 SOP |

三域在检索时会被 Stage1 智能路由用作优先级依据：规范查询优先命中 `standard`，案例检索优先命中 `case`。

### 5.2 新建 / 编辑

点击 **新建知识库**，填写：

- **名称**（必填）
- **知识域**（单选，**创建后不可更改**，因为它决定索引的领域标签）
- **责任人**：建议填到具体人，后续治理事项可自动分派
- **标签**：支持回车创建新标签，便于按主题筛选
- **描述**：说明收录范围与用途

### 5.3 列表操作

| 操作 | 说明 |
| --- | --- |
| 文档 | 跳转到该知识库下的文档管理页 |
| 编辑 | 修改名称 / 描述 / 责任人 / 标签 / 启用状态 |
| 删除 | **级联删除**该库下所有文档、切片与索引，不可恢复 |

页面顶部的六张统计卡展示：知识库总数、文档总数、知识切片、以及三域各自的文档数。

## 6. 文档与切片管理

### 6.1 上传工程资料

1. 点击 **上传工程资料**
2. 选择 **目标知识库**
3. 拖入或选择文件，支持 `.pdf` `.doc` `.docx` `.xls` `.xlsx` `.md` `.txt`，可多选
4. 填写工程元数据：
   - **标准编号**（如 `GB50204-2015`）—— 强烈建议填写，Stage3 会据此加权
   - 标准名称、专业、所属项目
   - **生效日期 / 失效日期** —— Stage7 据此做时效核查
   - 责任人、版本
5. 点击 **开始入库**

系统随后执行：解析（按页 → 段落 / 表格块）→ 工程感知切片（保留章节路径、表格完整性、识别强制性条文）→ Embedding → 同时写入向量库与 BM25 索引。

### 6.2 文本直接入库

适用于会议纪要、复盘报告、FAQ 这类没有源文件的内容：

选知识库 → 填标题、专业、责任人 → 粘贴正文（**支持 Markdown 标题**，系统据此建立章节路径）→ 提交。正文不少于 10 字。

### 6.3 元数据维护

点击 **元数据** 可在线修正标题、标准编号、标准名称、专业、**治理状态**、所属项目、责任人、摘要。

治理状态取值：

| 状态 | 含义 | 对检索的影响 |
| --- | --- | --- |
| `valid` 现行有效 | 正常使用 | 正常召回 |
| `need_update` 待更新 | 疑似过时 | 正常召回，但 Stage7 记为健康问题 |
| `deprecated` 已废止 | 不再适用 | Stage4 重排序时降权，置信度计算记惩罚项 |
| `draft` 草稿 | 尚未定稿 | 正常召回，标注为低可信 |

### 6.4 切片查看

点击 **切片** 打开抽屉：

- 支持在切片内搜索关键词（同时匹配正文 / 章节路径 / 条文号）
- 强制性条文以红色 Tag 标识
- 每条展示序号、条文号、页码、字符数、章节路径

用于资料员核查切分质量。若发现切分明显不合理（如表格被拆散），可调整切片参数后 **重建索引**。

### 6.5 重建索引

切片策略或 Embedding 模型变更后使用。点击 **重建索引** 将重新执行：解析 → 切片 → Embedding → 双索引。文档 `status` 字段会依次经历 `pending → parsing → indexing → ready`。

## 7. 知识治理闭环（Stage7）

这是让知识库"不腐烂"的核心模块，分四个 Tab。

### 7.1 知识健康度

- **健康评分**（仪表盘）：综合文档时效、责任人、重复度、解析成功率
- **统计卡**：知识库数、文档总数、知识切片、现行有效、待更新、已废止、解析失败、待办问题数
- **健康问题清单**：逐条列出问题类型、严重度、文档、问题描述、处置建议

问题类型与建议处置：

| 类型 | 含义 | 建议动作 |
| --- | --- | --- |
| `expiring_soon` 即将失效 | 临近失效日期 | 提前准备替代版本 |
| `expired` 已过期 | 超过失效日期 | 标注 `deprecated` 并补充新版本 |
| `no_owner` 缺少责任人 | 未指定 owner | 指派责任人 |
| `duplicate` 疑似重复 | 标题/内容高度相似 | 合并去重 |
| `stale` 长期未更新 | 超过阈值未修改 | 核对是否仍有效 |
| `empty_summary` 缺少摘要 | 无摘要 | 补充摘要提升检索质量 |
| `parse_failed` 解析失败 | 文件无法解析 | 查看错误消息，必要时手动转码 |
| `no_chunk` 无有效切片 | 切片数为 0 | 检查文件内容或重建索引 |

### 7.2 治理事项

事项状态流转：`open 待处理` → `in_progress 处理中` → `resolved 已完成` / `ignored 已忽略`

事项类型：

| 类型 | 含义 |
| --- | --- |
| `expire_check` | 时效核查 |
| `duplicate_merge` | 重复合并 |
| `gap_fill` | 知识盲区补录 |
| `conflict_resolve` | 冲突消解 |
| `quality_fix` | 质量修复 |
| `owner_assign` | 责任人指派 |

两种创建方式：
- **自动生成治理事项**（页面右上角按钮）：基于最新健康报告批量创建
- **新建事项**：手动填写类型、标题、知识库、优先级、责任人、说明

### 7.3 知识盲区

数据源是低置信 / 无召回的提问日志，按提问次数降序：

- 展示问题、提问次数、平均置信度、补录建议
- 点击 **生成补录事项** 一键把盲区转成治理事项，无缝对接治理流程
- 可切换统计窗口：近 7 / 30 / 90 天

**优先级建议**：先补"提问次数多 + 平均置信度低"的问题，投入产出比最高。

### 7.4 运营报告

按 7 天（周报）/ 30 天（月报）生成：

- **流量**：提问总数、未答问题数、有效回答率
- **质量**：平均置信度
- **性能**：平均响应耗时
- **增量**：新增文档、新增切片
- **热点主题 TOP**：高频问题主题
- **知识盲区 TOP**：待补录问题
- **运营建议**：自动生成的改进方向

可直接作为周会 / 月会的知识库运营汇报材料。

## 8. 使用技巧

### 8.1 提高检索准确性

- 上传文档时**务必填写标准编号与专业**——Stage3 会对匹配 `standard_code` 的切片额外加权
- 维护好 `effective_date` / `expire_date`，系统会优先推荐现行版本
- 把确认失效的文档改成 `deprecated`，它们在重排序时会被降权

### 8.2 提升问答质量

- 提问尽量具体："C60 冬期施工养护时间" 优于 "混凝土养护"
- 填写工程上下文，让 Stage2 改写时更聚焦本项目
- 用 **知识片段检索** 先验证知识库是否覆盖，再决定是否需要补录

### 8.3 团队协作

- 在文档元数据中标注责任人，治理事项可自动分派
- 用会话列表按主题分隔讨论（如"C60 养护"、"深基坑监测"）
- 建立周度节奏：每周看一次运营报告 → 处理知识盲区 → 关闭治理事项

## 9. 常见问题

**Q1：上传文档后提问仍然找不到？**
先打开切片抽屉确认有内容；若为空，点击"重建索引"；若仍失败，查看文档列表中"处理状态"列的错误提示（鼠标悬停可见 `error_msg`）。

**Q2：置信度普遍偏低怎么办？**
说明知识库覆盖不足。查看运营报告的 `knowledge_gaps`，按提问次数优先补录对应资料。

**Q3：如何切换到真实大模型 / Milvus？**
复制 `deploy/.env.example` 为 `.env`，修改 `LLM_PROVIDER=openai`、`EMBEDDING_PROVIDER=openai`、`VECTOR_BACKEND=milvus` 及对应连接参数，重启服务。切换 Embedding 后需对全部文档执行一次重建索引。

**Q4：如何重置演示数据？**
```bash
# 本地
cd backend && python scripts/seed_data.py --reset
# Docker
docker compose exec terraforge python scripts/seed_data.py --reset
```

**Q5：平台会不会编造答案？**
不会。LLM 严格基于 Stage5 构建的上下文生成，提示词明确禁止推断性扩展。召回为空时直接返回"知识库暂未收录，请补充相关资料"，并把该问题记入知识盲区。

**Q6：怎么定位某次回答的完整过程？**
每个响应都带 `X-Trace-Id` 响应头，用该 ID 在 `logs/terraforge.log` 中检索即可串联全链路日志；前端"执行链路"面板也展示了同一次请求的 Stage 明细。
